## Структура проекта

* `index.html` — главная страница
* `blog.html` — статья блога
* `src/scss/` — исходники стилей

  * `abstracts/` — токены, контрольные ширины
  * `base/` — reset, типографика
  * `blocks/` — по файлу на каждый БЭМ-блок
  * `main.scss` — точка входа
* `css/style.css` — скомпилированный CSS
* `img/` — фото и иконки
* `docs/` — документация

  * `decomposition.md` — декомпозиция



## Запуск

```bash
npm install
npm run dev     # sass --watch, пересобирает на каждое сохранение
npm run build   # финальная сборка, сжатый css/style.css
```

## Что решил сам и почему

1. **Адаптив.** В макете есть только 1440 px, поэтому 768 и 360 — импровизированная раскладка, по mobile-first: сначала одна колонка, дальше расширяется. С 1024 px «Recent stories» превращается в две колонки. Карточки стран и Highlights сделал через `grid auto-fit`, чтобы не плодить медиазапросы там, где это не нужно.
2. В макете нет состояний интерфейса, так что импровизация: у кнопок — hover с затемнением и лёгким «выпрыгиванием» тени, карточки при hover приподнимаются, ссылки подчёркиваются. Везде виден `:focus-visible`. Плюс `prefers-reduced-motion` — у кого отключена анимация в системе, у того анимации и тут не будет.
3. **Ссылки без реальной логики:** поиск, профиль, «Watch highlights», play — просто `href="#"`, по заданию тут ничего кликабельного не нужно. «Share your story» ведёт к форме (`#join`), Story в шапке = Blog в подвале = один и тот же `blog.html`, Gallery → `blog.html#highlights`, Contact Us → подвал.
4. **Форма:** оба поля выбора («Country of Destination» и «Shooting category») сделал как обычный `select` — со своей стрелкой и подписью, которая уезжает вверх при выборе. Варианты в списках по логике макета.
5. Шрифты Changa One и Roboto подключены локально (`fonts/`, брал через @fontsource), чтобы не грузить их с внешнего сервера.
6. Крупные размеры текста — через `clamp()`, чтобы не писать отдельный размер под каждую ширину экрана. Пара очень похожих значений в макете округлил до одного (например 18/33 и 18/34 → 18/33).
7. Весь контент на английском, поэтому `lang="en"` на обеих страницах.
